# 功能登记表（FEATURES）

核实基线：分支 custom/prod，提交 838b1dc4f（2026-10-22）。以代码为准；本表与代码冲突时，改本表。行为细节（请求怎么走、选号怎么选）见 `docs/CURRENT_BEHAVIOR.md`，本表只回答「有什么功能、在哪配、在哪生效、谁守卫、哪来的」。

**怎么用这份登记表**
1. **加功能、加设置之前先查本表**：已有同类就扩展它（同一个入口、同一个读写点），不要另起一套。
2. **改或删功能，必须同步更新对应行**（「生效位置」「测试」两列最容易过期）；行为变了，还要改 `docs/CURRENT_BEHAVIOR.md`。
3. **删功能要在第 9 节「已移除」登记**：写清为什么移除、哪个提交、替代方案。
4. 写法约定：路径相对仓库根；函数只写名字不写行号；拿不准的写「待核」（= 未核实）。每张表的第 8 列「备注与已知限制」写在表下的项目符号里，按功能名对应。

总览：「官方」= 上游 Wei-Shaw/sub2api 原有（以分叉点 be6cd1250 即约 v0.1.156，以及从上游 v0.2.16 回灌的功能为准）；「fork」= 本 fork 新增；「官方，fork 改动」= 官方功能但本 fork 改过行为。

名词：「设置」= 数据库 `settings` 表里的键（管理端系统设置页可改）；「配置」= config.yaml 里的键（样例见 `deploy/config.example.yaml`）；`extra` = `accounts.extra` 这一列 JSON；「调度快照」= Redis 里缓存的、选号用的账号精简副本；「粘性会话」= 同一段对话尽量落在同一个账号上；「槽」= Redis（内存缓存数据库）里的计数名额，占一个、用完释放；RPM = 每分钟请求数；OAuth / Setup Token = Claude 订阅账号的两种凭据（OAuth 是授权令牌，Setup Token 是只有推理权限的长期令牌）；「水合」= 选中账号之后，用完整账号替换调度快照里的精简副本；Ent schema = 数据库表结构的 Go 定义（`backend/ent/schema`）；JSONB = PostgreSQL 的 JSON 列类型。设置页（侧栏「系统设置」）页签真名：通用设置 / 登录条款 / 功能开关 / 安全与认证 / 用户默认值 / 网关服务 / 邮件设置 / 数据备份 / 支付设置 / 供货商（个别界面提示文案写的「常规」「网关」是不准确的简称）。

备注与已知限制：
- **容量档位模板**：写入校验——key 不超过 20 个字符、不含 `/`、不能叫 `custom`、不重复；并发 1–50（并发 0 在槽位逻辑里是「不限」，所以下限是 1）、会话数 0–50、RPM 0–500、5h 额度 0–1000（其余三项 0 = 不限）；4 个数值（并发、会话数、RPM、5h 额度）两两不同；`default_key` 必须存在；供货商账号还在用的 key 不能改名或删除（`CAPACITY_PRESET_IN_USE`）。读路径宽松：坏数据回落种子并打警告。**改模板只影响之后套用的账号**；存量账号靠批量编辑或「应用到存量」（第 6 节）。账号表单与供货商面板里的档位名由 4 个数值反推（不含降速开关），后端 `providerTierMatchesAccount` 与前端 `matchPreset` 必须同口径。前端护栏常量在 `frontend/src/constants/capacity.ts`，与后端上限要一起改。处理器挂在 `ProviderHandler` 上（见第 10 节）。
- **动态降速**：曲线 = 利用率 < 50% 系数 1；50%–80% 线性降到 0.5；80%–95% 线性降到 0.2；≥ 95% 直接 0.1（95% 处有一次跳变）；利用率 > 1 钳到 0.1；没数据或 NaN 当 1；账号系数 = min(5h 系数, 7d 系数)。**有效值 = 数值 × 系数，向下取整，下限 1；数值 ≤ 0（不限）原样不动，不会被降成 1。** 刻意不缩放：黄区宽度、`max_sessions`、`window_cost_limit`。供货商自定义档账号恒开降速（第 6 节）。批量更新会对非 Claude OAuth/Setup Token 账号剔除容量键（`StripCapacityExtra`）。与请求伪装无关。
- **用户消息限速（UMQ）**：账号级优先于全局；只作用于 Claude OAuth/Setup Token 账号，且只在 `/v1/messages` 入口（第 10 节）；账号上选「关闭」= 删键 = 跟随全局，压不过全局开启。延迟算法见 `docs/CURRENT_BEHAVIOR.md` 第 1 节第 7 步。
- **负载因子**：批量编辑里勾选后留空或填 0 是空操作（第 10 节）；供货商上号与「应用到存量」时，`load_factor` 与并发对齐。
- **选号快照登记表**：新增「选号阶段会读」的 extra 键 = ① 登记到清单 ② 在 `contractScenarios` 加用例；选中账号之后才读的（转发、计费、UMQ 延迟）读的是水合后的完整账号，不用登记。API Key / Bedrock 账号自设额度（总 / 日 / 周共 14 个键）与 OpenAI 透传开关（2 个键）都已登记并有对拍用例；键被误删时 `TestSchedulerProjectionContract_RegistryShape` 的 `must` 清单会变红。同类的「窄查询」风险（只选部分列的专用查询，如公开号池健康页的 `ListPoolHealthAccounts`）要在真实库上测，见第 3 节。

## 2. 请求伪装

「请求伪装」= 让转发到 Anthropic 的请求更像真实的 Claude Code 客户端，降低账号被识别的风险。账号弹窗里的「请求伪装」块（TLS 指纹、会话 ID、缓存 TTL、自定义转发地址，仅 Anthropic OAuth/Setup Token 账号）与「容量与节流」卡相互独立；全局开关集中在 设置 → 网关服务 →「请求转发行为」卡。伪装只在「账号是 OAuth/Setup Token 且客户端不是真 Claude Code」时触发（`Forward` 里的 `shouldMimicClaudeCode` 判定，见 `docs/CURRENT_BEHAVIOR.md` 第 1 节第 8 步）。

**踩坑提醒**：请求体改写函数 `normalizeClaudeOAuthRequestBody`（`backend/internal/service/gateway_claude_oauth_body.go`）有 **3 个调用点**——`GatewayService.Forward`（`backend/internal/service/gateway_forward.go`，原生 `/v1/messages` 主路径）、`applyClaudeCodeOAuthMimicryToBody`（`backend/internal/service/gateway_claude_oauth_body.go`，被 `ForwardAsChatCompletions` 与 `ForwardAsResponses` 复用）、`ForwardCountTokens`（`backend/internal/service/gateway_count_tokens.go`）。只改一处，改写会在另一条路径完全不生效，单测全绿也会漏。

备注与已知限制：
- **TLS 指纹模拟**：**缺省 ≠ 关**——在「模拟 Claude Code」路径（OAuth/Setup Token 账号且请求方不是真 Claude Code）缺省也用内置指纹，显式 false 才真关；账号测试连接、用量查询、API Key 透传、模型列表探测这些旁路，缺省不伪装。新建弹窗默认写 true；编辑弹窗没碰过开关就既不写也不删，拨过才写显式布尔。登录类请求（OAuth 换票、刷新）另用 Chrome 指纹（`createReqClient`），与此无关。
- **会话 ID 伪装**：15 分钟是写死常量，且是滑动窗口（每次请求续期）；`extra.account_uuid` 为空、或开了「Metadata 透传」、或 `metadata.user_id` 缺失时静默不生效——供货商上号因此要把 `account_uuid` 从 credentials 复刻进 extra（第 6 节）。
- **缓存 TTL 强制替换**：只改响应 usage 与计费，不改请求；账号开关优先于全局「Anthropic 缓存 TTL 注入」；全局开着时，没配账号级覆盖的 OAuth 账号也会把 usage 归回 5m 档。
- **自定义转发地址**：保存时不校验；请求时默认只检查 URL 格式（http/https、端口），无白名单、无内网拦截，除非开启配置 `security.url_allowlist.enabled`；启用但 URL 为空时请求报错；账号「测试连接」不走它。
- **机器档案**：与已移除的 persona 层无代码依赖，仍在用（第 9 节）；复制账号会复制同一设备号；存量账号在首次转发时补写。
- **伪装守卫模式**：代码缺省 warn（种子、规范化函数、读库失败兜底、前端表单初值 4 处一致）；block 时 count_tokens 路径返回 500 `Failed to build request`，主路径的普通错误由 handler 兜底成 502（读代码推断），具体原因都只在日志；真 Claude Code 客户端与 API Key 账号不被审计。线上库当前值待核：提交 7b8becd9e 到 cdaa930e8 之间新建的库，种子是 block，且不会自动改回。
- **标定 profile**：拒收条件——schema 不符、cli_version 不是三段版本号或不在 UA 里、指纹守卫未过、无 beta 规则；缓存是进程内的（约 60 秒），多实例无跨实例通知。CI 的 `claude-calibration` job 定时跑（cron 每 6 小时），`.github` 目录被 git 跟踪。Admin API Key 在 设置 → 安全与认证 里生成（部分文档写成「网关服务」，不准确）。
- **thinking 剥离 / usage 扣除**：只覆盖主 `/v1/messages` 的响应处理；兼容层（chat/completions、responses）会写标记但没有地方读它，其回包是否漏出空 thinking 块、input_tokens 是否偏大待核。usage 扣除只改展示不改计费；注入量 ≥ 上游总量时原样透传。
- **伪装 Profile 选择器**：后端对任何输入都返回同一份默认 profile（`ResolveClaudeCodeMimicryProfile` 的两个分支都返回默认 profile，当前默认 ID 是 `cc-2.1.211-sdk-cli-linux-x64`），所以下拉只有一个选项，实际是空操作。设置页直接展示服务端返回的 ID，不再自带「当前版本」常量（此前写死 2.1.206，与网关实际使用的 2.1.211 不一致，已修）；后端升级默认版本时前端不用改。
- 同族改写函数的调用点数各不相同（`git grep` 实测，非测试代码）：`normalizeClaudePromptEnv` 2 处（不含兼容层）、`normalizeClientDatelineIfEnabled` 1 处（仅 `Forward`）、`injectAnthropicCacheControlTTL1h` 1 处（仅 `Forward`）、`rewriteMessageCacheControlIfEnabled` 3 处、`markInjectedThinkingIfAdded` 2 处。新增改写前先列全调用点。

备注与已知限制：
- **用户并发上限**：管理员在后台「创建用户」不套用「用户默认值」（那组默认值只用于自助注册与第三方登录建号）；批量改并发只有接口 `POST /api/v1/admin/users/batch-concurrency`，无界面。
- **用户 RPM、分组 RPM 与专属覆盖**：这几项**并行生效、任一超限即 429**；用户×分组覆盖值存在时**替代**分组的 `rpm_limit`（覆盖值 0 = 该用户在该分组免检）；用户自己的 `rpm_limit` 始终另外生效，不会被分组或覆盖顶掉；Redis 出错放行。**界面文案过时（官方遗留）**：用户编辑弹窗写「仅在所用分组未设置 rpm_limit 时作为兜底生效」、分组弹窗写「一旦设置即接管该用户的限流」，都与行为不符（第 10 节）。
- **API Key 额度与限额**：都是用户给自己的 Key 设的自限，管理端没有入口；按实际扣费额累计，最后一单可略超。总额度与过期在鉴权中间件里检查，5h/1d/7d 窗口在计费资格检查里检查（不在中间件）。`run_mode=simple` 时整段计费检查跳过（`docs/CURRENT_BEHAVIOR.md` 第 1 节第 1 步）。窗口是固定窗口、非滑动。
- **订阅分组额度**：窗口自首次使用激活（日 24 小时、周 7 天、月 30 天，非自然月）；有效期不超过 1 天的「日卡」，日额度一次性不重置。
- **分组倍率**：是计费不是限流；专属倍率有进程内缓存，改后最长约 30 秒生效。
- **Claude Code 专属分组**：无降级分组时，`/v1/messages` 上客户端见 503（读代码，未发请求验证）；`/v1/chat/completions`、`/v1/responses` 对此类分组直接 403；降级只换账号池，计费与 RPM 仍按 Key 原分组。
- **模型路由**：是「优先」不是「限定」；多条通配同时命中时选哪条不确定（Go map 遍历无序）；命中路由不经「混合池权重」。
- **复合分组**：**后台创建/更新分组的请求体对平台做白名单校验，白名单不含 composite**，界面选 Composite 提交会被 400 拒绝（读代码，未发请求验证，第 10 节）；回灌不完整：无路由管理页、选号按 endpoint=any 解析；`backend/cmd/server/wire_gen.go` 的三行手工绑定，重新用 wire 生成会静默丢掉（编译与测试都不报错，运行时显式路由表失效、只剩按模型名前缀识别）。
- **混合池权重**：只对 API Key 账号，且所在分组开启混合池权重才生效；开启后默认 100/0 会把所有 API Key 账号排除在该分组调度之外，须把 API Key 池权重调到大于 0；粘性命中与模型路由命中不受它约束；与账号级「混合调度」（`mixed_scheduling`）是两回事。
- **新增分组字段的缓存坑**：网关热路径读的分组字段来自「API Key 认证快照」而不是实时查库，新增分组字段必须同步 `backend/internal/repository/api_key_repo.go`（`GetByKeyForAuth`）、`backend/internal/service/api_key_auth_cache.go`（`APIKeyAuthGroupSnapshot`）、`backend/internal/service/api_key_auth_cache_impl.go` 三处。

备注与已知限制：
- **站点总开关**：关站后，注册、发验证码、供货商登录返回 403 `PROVIDER_PORTAL_DISABLED`；其余 `/api/v1/provider` 下的接口返回 404；已签发的令牌不吊销；管理端接口不看这个开关；前端页面不读这个开关（页面仍能打开，接口失败时才报错）。开启时后端校验：至少有一个启用的托管类型，且默认托管类型已设置并启用。
- **注册**：不看 `registration_enabled`；`/api/v1/provider/auth` 下的公开接口没有 Cloudflare Turnstile 人机验证与 IP 限流（发验证码只有同邮箱 60 秒冷却）。
- **上号**：账号类型（OAuth/Setup Token）× 授权方式（Session Key/授权链接）= 4 种组合；Session Key 一行一个可批量（前端逐条串行）；同一供货商内按 `account_uuid` 去重；恒走 claude_code 授权档案，Chrome 授权在后端被硬拒绝；账号的分组由托管类型唯一决定；没有「每位供货商最多上多少号」的限制；供货商提交的 `extra` 一律被白名单丢弃（`providerSubmittableExtraKeys` 目前为空）。
- **IP 来源策略**：策略后端硬校验（违规 400 `PROXY_MODE_NOT_ALLOWED`）；`auto_assignable` 默认关，所以默认没有平台 IP 可分（无可用 → 409 `AUTO_PROXY_UNAVAILABLE`）；绑定数按代理上所有未软删账号计，不只是供货商账号。
- **供货商设置**：速率数值不在这里（在容量档位模板，第 1 节），这里只存「开放哪些」；`provider_enabled_tier_keys` 缺失、空串、非法 JSON 或 null = 模板表全部开放，显式空数组 = 一个都不开放（保存时至少 1 个、必须存在于模板表、不能写 `custom`）；自定义档护栏 `provider_custom_tier_caps` 种子为并发 10、会话 10、RPM 100、5h 额度 200，供货商提交的值必须大于 0 且不超护栏；**自定义档账号恒带动态降速**（`resolveCustomTier` 写死 true，只在上号与自助换档两条路径强制，管理员事后仍可手动关）；结算时区默认 Asia/Shanghai，封账冷却默认 600 秒（范围 60–86400）。`provider_default_tier` 仍在使用（默认档位），只有 `provider_capacity_tiers` 被搁置（第 9 节）。
- **强制项**：预热拦截 = 对 Claude Code 的标题生成、预热等辅助请求本地回假响应、不消耗上游额度；供货商重新授权时，只有 `intercept_warmup_requests` 会被重新强制写成 true（会盖掉管理员关掉的设置）；不强制：养号、`rpm_strategy`。
- **`accounts.provider_tier` 列**：它是「成员标记」，**展示标签由数值反推**：供货商看到的档位名按 4 个数值（并发、会话数、RPM、5h 额度，不含降速）反推（`ResolveProviderAccountTier`），不读本列。两者会分歧——管理员改了数值后供货商看到「自定义」，但本列仍是旧 key，「应用到存量」仍会按旧 key 把它覆盖回模板值。`custom` 作为列值 = 自定义档，不参与「应用到存量」。
- **`accounts.provider_user_id` 列**：不是自己的账号一律返回 404（不是 403）；同一个 Anthropic 账号可被不同供货商各上一次；账号软删除后归属仍保留。
- **双向隔离**：新增消费侧路由组必须自己挂 `ProviderDenyConsumerRoutes`（目前只在 user 与 payment 两处挂了；`/auth/me` 等未挂）。
- **我的账号**：视图是显式字段白名单，不含 extra、代理、分组；暂停/恢复与管理员共用同一个 `schedulable` 标志（见下面限制）。
- **应用到存量**：重算数量与 `expected_changed` 不符回 409 `PRESET_APPLY_CONFLICT`、一行都不写（只比数量，不比账号集合）；缺 `expected_changed` 回 400 `EXPECTED_CHANGED_REQUIRED`；写入是一条 `BulkUpdate`：并发列与 `load_factor` 都写成档位并发，`extra` 只合并 4 个键，只要有 1 项不同，6 项都会被重写成模板值；`custom` 档不能回填（400 `CUSTOM_TIER_NOT_BACKFILLABLE`）；只认已对供货商开放的档位（否则 400 `INVALID_TIER`），而设置页对每个模板行都显示「应用到存量」。
- **停用级联**：`disabled` 无条件触发（重发可重试失败的暂停）；`active` 还要求旧状态是 `disabled`；标记不在供货商视图里、不可由请求提交（`providerSubmittableExtraKeys` 为空 + `SanitizeProviderExtra`）、不在容量键里、不进调度快照白名单（暂停靠 `schedulable` 列）。级联失败返回 500，此时用户状态已落库；没有数据库审计表，只写应用日志。
- **对账与封账**：只算标准价（不乘分组/用户/账号倍率），无「分成比例」设置；下线账号的用量仍计入；封账终点 = 此刻减冷却期，冷却窗口内的用量顺延到下一期、不丢；`last_usage_id` 水位兜住迟到记录；封账在该供货商的 advisory lock（PostgreSQL 咨询锁）内进行；只有手动封账，无定时任务；无「已付款」状态；`void_reason` 只写库不读出；时区只影响按日明细的日期切分，前端没有页面渲染按日明细。
- **CSV**：账号名以等号、加号、减号或 @ 开头时会被前补一个单引号，防表格公式注入（前后端各一份实现，改要同步）；管理端「本期明细」的 CSV 是前端拼的，与后端导出的结构不同。
